# WorldBrief — Roadmap

# 中文版

## 项目路线图

WorldBrief 将分阶段推进。我们会先验证信息组织方式和用户需求，再决定是否开发完整的软件产品。

### 阶段一：明确方向与项目基础

**目标：** 说明项目要解决的问题、服务的人群和核心原则。

- [x] 创建项目 README.md
- [x] 明确项目愿景并创建 VISION.md
- [ ] 创建项目路线图
- [ ] 研究现有的新闻、信息聚合和 AI 学习项目
- [ ] 明确 WorldBrief 的差异化方向

**完成标准：** 项目的目标、边界和下一步工作清晰可见。

### 阶段二：建立可信信息源目录

**目标：** 帮助用户更方便地找到原始信息和可靠的背景资料。

- [ ] 设计信息源分类标准
- [ ] 整理国际组织和政府官方网站
- [ ] 整理大学、研究机构和公开数据平台
- [ ] 整理企业公告及其他一手资料来源
- [ ] 为每个来源记录名称、链接、主题和使用说明

**完成标准：** 形成一个有分类、有说明、便于查找的公开信息源目录。

### 阶段三：设计每日信息简报

**目标：** 用清晰、简洁的方式帮助用户了解重要事件。

- [ ] 设计每日简报模板
- [ ] 每条信息尽可能提供原始来源链接
- [ ] 补充事件背景和关键概念
- [ ] 区分已确认事实、官方表述、分析和不确定信息
- [ ] 制作少量示例，检验内容是否清晰易懂

**完成标准：** 读者能快速了解事件，并知道去哪里查看原始信息。

### 阶段四：设计 AI 引导学习流程

**目标：** 帮助用户从一个陌生主题开始，逐步建立基础知识。

- [ ] 设计主题学习路径模板
- [ ] 将复杂主题拆分为基础概念和进阶问题
- [ ] 为学习资料提供可追溯的来源
- [ ] 设计适合初学者的提问和探索方式
- [ ] 测试用户能否通过学习路径理解一个主题

**完成标准：** 用户能从新闻或问题出发，找到下一步值得学习的内容。

### 阶段五：验证最小可用版本

**目标：** 用尽可能低的成本检验整个产品构想。

- [ ] 选择少量主题开展试验
- [ ] 使用人工整理的内容验证工作流程
- [ ] 收集潜在用户反馈
- [ ] 判断哪些功能最有价值
- [ ] 根据反馈决定是否开发网站或其他工具

**完成标准：** 在投入大量开发时间或费用之前，获得初步的用户需求证据。

## 当前优先事项

目前优先完成阶段一，不急于开发软件。

接下来依次完成：
1. 研究现有项目。
2. 明确差异化定位。
3. 建立信息源政策与目录。
4. 设计每日简报和学习路径模板。

## 项目原则

- 先验证需求，再增加复杂功能。
- 优先使用低成本、易维护的方案。
- 不承诺完全自动化或绝对准确。
- 让用户能够查看来源并独立判断。
- 根据真实反馈调整路线图。

# English Version

## Project Roadmap

WorldBrief will develop in stages. We will first validate the information structure and user needs before deciding whether to build a full software product.

### Phase 1: Define the Direction and Foundations

**Goal:** Clarify the problems, audience, and principles of the project.

- [x] Create README.md
- [x] Define the project vision in VISION.md
- [ ] Create the project roadmap
- [ ] Research existing news, information aggregation, and AI learning projects
- [ ] Define WorldBrief's differentiation

**Completion criteria:** The project's goals, boundaries, and next steps are clear.

### Phase 2: Build a Trusted Source Directory

**Goal:** Make original information and reliable background materials easier to find.

- [ ] Define source categories
- [ ] Collect official websites of governments and international organizations
- [ ] Collect universities, research institutions, and open-data platforms
- [ ] Collect corporate announcements and other primary sources
- [ ] Record each source's name, link, topics, and usage notes

**Completion criteria:** A categorized, documented, and searchable public source directory.

### Phase 3: Design the Daily Briefing

**Goal:** Help readers understand important developments clearly and efficiently.

- [ ] Design a daily briefing template
- [ ] Provide original-source links whenever possible
- [ ] Add context and key concepts
- [ ] Distinguish confirmed facts, official statements, analysis, and uncertainty
- [ ] Create a small number of examples to test clarity and usefulness

**Completion criteria:** Readers can understand an event and know where to find the original information.

### Phase 4: Design AI-Guided Learning

**Goal:** Help users build foundational knowledge of unfamiliar subjects.

- [ ] Design a learning-path template
- [ ] Break complex topics into foundational concepts and advanced questions
- [ ] Provide traceable sources for learning materials
- [ ] Design beginner-friendly ways to ask questions and explore
- [ ] Test whether users can understand a topic through the learning path

**Completion criteria:** Users can move from a news item or question to meaningful next steps for learning.

### Phase 5: Validate a Minimum Viable Product

**Goal:** Test the product concept at the lowest practical cost.

- [ ] Pilot a small number of topics
- [ ] Validate the workflow with manually curated content
- [ ] Gather feedback from potential users
- [ ] Identify the most valuable features
- [ ] Decide whether to build a website or other tools based on feedback

**Completion criteria:** Obtain initial evidence of user needs before investing substantial time or money in development.

## Immediate Priorities

Focus on Phase 1. Software development is not the priority yet.

Next steps:
1. Research existing projects.
2. Clarify differentiation.
3. Establish source policies and a source directory.
4. Design the daily briefing and learning-path templates.

## Project Principles

- Validate demand before adding complexity.
- Prefer low-cost, maintainable solutions.
- Do not promise complete automation or absolute accuracy.
- Enable users to inspect sources and make independent judgments.
- Adjust the roadmap based on real feedback.
